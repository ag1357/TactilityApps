Electrical finding: with the pad unpowered, the external bus polls failed
with "i2c.master: clear bus failed" + "reset hardware failed" (26
occurrences; STEMMA pull-ups tied to a dead rail hold SDA low). After
powering the pad, the bus recovered with no reboot: 3 transport
disconnects total, then a clean reconnect and zero further disconnects
across the rest of the session. Source-isolated: gameplay, rendering,
keyboard input and the input sampler continued unaffected throughout.

Hands-on (user quick test, telemetry in /tmp/device-serial-i2c.log):
- Controls -> Bind New captured analog joystick values (raw 395, 20 seen)
  during binding.
- Joystick bound to MOVE_X/MOVE_Y: full range to +/-1000 with
  intermediate values (-986, -195, 43, 251, 680, 825, 995...) observed;
  clean return to zero after release, no stuck axis.
- Held button state: held bitmask 32 (Start) observed, with simultaneous
  joystick values [680,825] - button+joystick chord works.
- No stuck state after release: values, held and axes all return to zero.
- User reports commands "much more responsive" than the BLE keyboard.
- Input sampler mean ~19.7 ms per acquisition vs 10 ms target while
  rendering at ~210 ms/frame; max sample gap 130 ms (one render frame),
  no gaps; zero dropped events.
